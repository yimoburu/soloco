# Protected peer source profile

The protected companion separates original source evidence from permission to
act. Its private runtime checks session ownership, current input and exact wire
projection. A matching string, serialized receipt or source label cannot replace
those checks. Native readiness still requires an actual qualified binary, host,
authority, account route and end-to-end acceptance for the declared profile.

## Source boundaries

| Input or boundary | Original producer and checks | Capability boundary |
|---|---|---|
| Accepted user input | Actual Core Session admission, queue order, private owner and one-consume materialization | Generic injection and restored JSON cannot issue a fresh admission. |
| Model selection | Original bundled catalog bytes and the actual concrete manager's ownership | A bundled entry does not establish account availability or provider consent. |
| Base instructions | Original selected model template or supported original direct configuration field, actual renderer and copy spans | Equal text, a public constructor or a forwarded manager cannot supply the original selection. |
| Generated instructions | Supported concrete world-state controls, original fragments, assembly and live history occurrence | Custom or unresolved producers retain their missing-origin holds. |
| Final input | Same Session and private ModelClient issuer, original input bytes and the enumerated source-owned wire transform | Dropped, reordered, altered or injected input cannot inherit the old projection. |
| Tool declarations | Original typed encoder and complete fixed five-tool schema inventory | An arbitrary AdditionalTools item or a matching name is insufficient. |
| Send currentness | Admission/closure revokes the epoch before awaiting the writer; the gateway checks each send poll | Cancellation does not establish provider termination or close an uncertain operation. |

Runtime-only witnesses are omitted from serialization and schema output. Restored
history retains its actual uncertainty. Public carrier types transport data;
private original producer identity and current runtime ownership confer the
limited evidentiary meaning described above.

## Explicit nonincremental RLite profile

The protected scoped configuration explicitly selects
`features.incremental_tools=false`. This leaves immutable model catalog fields
unchanged, including `use_responses_lite` for a genuine bundled RLite model. It
also leaves the original normal bootstrap, AuthManager, provider identity and
managed authentication requirements in their existing roles.

The scoped configuration appends the source-owned feature selection after the
original CLI preferences. It checks the actual typed feature set after building
that configuration, before scoped start, before the effective configuration load
and again after the awaited effective load. A managed requirement or later
configuration that enables incremental tools is rejected. The original normal
host default is not relabeled as this scoped profile.

The fresh RLite wire path uses the actual typed tool encoder, with the tool and
base prefixes in the original client's order. Its source witness must bind the
same owner and exact pre/post input bytes. The final API boundary still checks
the entire source-owned five-tool inventory. Ordinary Responses input retains
its separate exact normalization path.

This fresh instruction profile alone does not supply original ancestry for default
incremental-tool history, omitted base/tool state, model-response history, tool results, media,
compaction, restored history or unsupported extension/managed instruction
producers. Those paths remain held until their actual producers and projections
are implemented and qualified. A fresh-request source test is not an end-to-end
CoS workflow. The continuation below adds source mechanics for supported live
responses and fixed-tool results; executable qualification remains separate.

## Source and binary association

The portable source package binds the complete fixed upstream Rust inventory,
all overlay files and modes, the accepted Cargo lock and the pinned toolchain.
The preparer reconstructs that complete graph; missing or extra source entries
are rejected. The overlay count is an exact source-owned constant for this
package rather than a caller-selected allowance.

The builder derives the canonical `compiled-source-manifest.json` from the
complete graph and passes its hash through the source-owned compile environment.
A caller-supplied hash cannot qualify an earlier binary. Build receipts retain
the source association, selected SDK and bounded execution result. Building or
passing component tests does not populate the native-qualified slot.

A later source change requires a new complete input manifest and affected
qualification. Historical source tests, tiny build controls and an older
unassociated development binary keep their original meanings.

The [component descriptor DATA library](component-descriptor-data.md) inspects an
originally selected build without making it executable. It preserves the raw
package/receipt JSON, original-to-sealed path mapping and read-only file semantics.
Its opaque DATA handle is not an interpreter, execution grant or runtime slot.
The separate executable bridge below implements deployment, Node loading and
private-FD joins in source; their genuine runtime qualification remains required.
