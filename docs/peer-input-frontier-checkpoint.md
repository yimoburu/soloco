# Original administrative checkpoints

This SOURCE component carries an independently checked input frontier across
fixed original administrative producers. It does not grant execution, accept
business output, release an UNKNOWN reservation or renew an allowance. The
original exact-current frontier and its overlapping support fences remain.

The initial closed purpose is `origin-frontier-seal`. Its actual selected
finite seal purpose must exist inside the original maintenance totals and
deadline. Preparation verifies the complete original DAG, exact current pins,
source custody and whole namespace before any put. A private same-transaction,
same-ledger branded plan supplies a deterministic checkpoint reference, the
complete preimage, contributors and original deadline. JSON, copied/inherited
plans, caller exclusions, ready/pending flags and read-only handles cannot
stage it. The backend performs its fixed full context/wire feasibility check
before the first staged checkpoint write.

Immutable checkpoint/pages store the full canonical preimage and namespace
vector. The small readset DATA projection is custody metadata, never a claim
that hashes were read as semantic input. It does not replace the complete
qualified meaning in the actual model context. A planned event sequence is
not a committed event or fabricated future hash. No checkpoint hashes itself
or a future command; the actual admission command points to the checkpoint.

Cold currentness verifies the actual original committed admission journal and
neutral fixed seal transition producer, reads the complete committed interval,
and compares every event change and every current namespace head. Unsupported
events, fields, producers and business changes Hold. Only after that complete
replay does a fixed authenticated historical view retrieve original immutable
values and rerun the unchanged strict original proof/custody validators.
Historical retrieval rewrites no raw value and supplies no caller ignore mask.
The returned actual maintenance/global spend is current; original semantic
items, markers, UNKNOWN, failures, recorded acceptance and spent units survive.

New UNKNOWN/rejected/Fail evidence and every late diagnostic journal Hold this
checkpoint subject. Namespace hashing alone does not semantically incorporate
new retained facts/chunks or required notices. Those originals remain readable
through their original producer and are not normalized away or backfilled as
positive closure. An owner diagnostic after unrelated resumed work is a
different contract; this component does not pause arbitrary later business.

The namespace, preimage, event and context bounds are retention/verification
bounds, not peak-memory/IO or whole-company fit claims. All genuinely changed
business/current meaning still requires real fresh bounded qualification under
the remaining original totals and deadline. Positive reuse of another producer
requires its fixed original transition assertion; missing producers Hold.

Before returning the private plan, preparation counts the exact staged
checkpoint pages/main and the fixed seal producer's positive lifecycle envelope:
eight work items, one command, slot, effect and conservatively one usage record.
It retains the existing 10,000 records per family, 30,000 total and 8 MiB readset
bounds, including future reference bytes and revision-width growth. The same
arithmetic runs on cold custody. The source writer separately checks its fixed
generated IDs and safe revision increments; callers cannot choose a reserve,
count, mask or enlarged capacity. Negative/late custody does not qualify the
positive path and retains its separate explicit retention/capacity Holds.

A later founder pause is an authority boundary, including when the company was
already paused. Positive frontier admissions, context/private-plan access and
checkpoint preparation/currentness require the fixed original selected
maintenance producer. The explicit maintenance pause generation must match the
original quarantine's companion company selection and the current company
generation. Constructing a new service or checkpoint cannot renew that
selection. Missing historical fields or unsupported rebinding Hold. Original
negative/late custody and historical proof retrieval remain nonauthorizing and
do not require an active positive selection.

Paused private membership bootstrap, owner intent/control/handover, and pending
incoming-owner semantic refresh require their own reviewed fixed producers.
Ordinary membership keeps its unpaused guard. The origin frontier service still
requires its actual active origin owner: a pending owner cannot inherit it by
changing actor/epoch/IDs. A future pending-only maintenance delegation must be
explicitly selected before handover within unchanged original budgets/deadline;
the corresponding fixed current assertion is absent here and remains Held.

The SOURCE-private `originalPeerInputFrontierMaintenanceLedger(api)` resolves
only the actual same-namespace service WeakMap handle, rechecks its bound
connection, current owner/pins/quarantine/authority/fences and returns the same
ledger to the fixed high-level launch facade. It supplies no caller-selected
ledger, profile, launch, provider, instruction or general configuration.

The two fixed optional source entries are checked directly with
`lstatSync(..., {throwIfNoEntry:false})`. Actual absence preserves the typed
missing-source Hold. Existing regular entries import without an error
classifier: original errors, causes, aggregate members and transitive failures
propagate unchanged even when public `code`/`url` fields resemble an absent
module. Stat-provider errors propagate; nonregular entries Hold. This is source
availability handling, not a concurrent-filesystem integrity attestation.
