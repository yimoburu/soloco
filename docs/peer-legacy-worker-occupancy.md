# Legacy local worker occupancy

This SOURCE component separates a historical job's local worker occupancy from
its retained UNKNOWN reservation and semantic outcome. It issues no execution,
release, acceptance, retry, ownership, notice-resolution or accounting authority.
The origin backend's mechanical-plan producer and both maintenance consumers
still need a coordinated, independently reviewed integration. They are absent
from this change. Missing integration holds; installing this module cannot
activate maintenance or ordinary work.

## Fixed original source producer

```js
const originalCapture = captureLegacyLocalWorkerOccupancyFrom(db);
const projection = inspectOriginalLegacyLocalWorkerOccupancy(originalCapture);
```

`db` must be the trusted host caller's actual `DatabaseSync` connection in an
already authenticated, paused-company, normalized-layout4 snapshot. The module
opens no file, transaction, worker or native session. A real SQLite object alone
does not authenticate an operator; the caller's supported owner path remains
required. Neither method accepts a job, selected list, proof, release Boolean,
policy choice, readiness flag or validator. The original capture is private
`WeakMap` state; serialization, matching DATA and a copied hash cannot mint it.
Inspection returns a copy of the exact captured DATA, with no new authority.

Capture reads the complete current source inventory, complete immutable vault
and complete event inventory. It checks raw UTF-8/hash integrity and canonical
logical job identities, including escaped keys. Bounded preparation requires at
most 10,000 rows per inventory, 64 MiB per body inventory, 16 MiB per value,
100,000 journal changes and 900,000 bytes for the complete projection. Current
reference-expanded bytes are separately bounded to 64 MiB before parsing;
deduplicated vault size cannot hide repeated expansion. Inventory metadata is
bounded to 4 MiB before collection. Traversed
JSON is also depth/node bounded. Over-capacity holds rather than claiming a
complete prefix. Original unknown fields remain preserved by their exact source
and immutable-value references; the projection does not summarize them away.

The fixed initial recipe is the reviewed SoloCo runtime `0.7.8` ordinary/durable
scheduler's three-job/assignment policy. The recipe pins the accepted engine and
model-process validator source hashes and reads those actual module files on
capture. The captured original `runtime_version` must match this reviewed recipe.
Missing or unsupported versions, changed source leaves, and unqualified policy
applicability hold. Compatibility lists and installed-team versions are not
substitutes. Any additional recipe requires explicit source review; no caller
can select one. Actual applicability to the imported historical cut must still
be part of the backend's exact mechanical-plan qualification.
Composing a changed engine also requires an explicit reviewed source-pin rebind,
even if the change is believed unrelated to this occupancy predicate.

Original queued/running jobs occupy capacity even with a release-looking flag.
A well-formed terminal job becomes locally unoccupied only after all current
invocations have their original, same-job/instance/worker/host
requested → born → closed journal and immutable-value lineage, followed by a
matching persisted `model_process_closed` release. Failed and completed outcomes
use the same local closure proof. No zero exit code or semantic Pass is inferred.
The existing mechanical QA caller's stronger success conditions are separate.

Missing attempt metadata is not proof that a model was never invoked. This first
recipe conservatively counts unproved prelaunch failures too; a future supported
not-started recipe would require its own original producer proof. A malformed
job has unknown capacity and holds the shared view. A runtime-task-only job is
counted even if an older importer omitted its reservation row.

Every local proof states `scope:'original-CLI-child-only'` and
`whole_domain_qualified:false`. It proves neither descendants nor remote effects
closed. Failed status, original timeout/failure evidence, resource reservations,
notices, old units and usage stay unchanged. Provider exceptions propagate as
their original objects, including lookalike codes, causes and AggregateError
members; only errors generated by this module's private validation can become
an unproved local fact.

## New immutable integration contract

The following is a prospective record contract, not an existing importer API:

```js
{
  kind: 'legacy_local_worker_occupancy',
  protocol: 'legacy-local-worker-occupancy-record-v1',
  origin_id,
  plan_id,
  plan_sha256,
  source_cut_sha256, // exact whole origin cut qualified by the backend
  projection,        // complete fixed-producer DATA, not caller proof
  projection_sha256,
  release_authority: false,
  whole_domain_qualified: false
}
```

The frozen backend must include the exact original partition, source/proof
manifests and recipe in its mechanical-plan/review subject before application.
A closed mechanical-review journal rule is a required integration dependency.
It must account explicitly for the new review job and plan/QA journal additions
between baseline and apply.
Matching only the baseline hash or allowing a caller exclusion would be wrong.
This component neither implements nor establishes acceptance of that rule, and
supplies no new accepted-review issuer.

After the real fixed mechanical validator succeeds, the canonical initial
quarantine writer must produce this revision-one work item and reference it as
`control/origin.legacy_worker_occupancy_ref` in the same `origin.quarantined` P1
event containing `origin.paused_quarantine_committed`. It must bind the exact
origin, plan and current source-cut hashes. All legacy reservations remain
UNKNOWN, `release_authority:false`, with their exact sources and units. No
existing quarantined company can acquire this contract by manually attaching a
record: a separate supported reconciliation path would need its own review.

This module has no writing API and no public/model tool. The production
mechanical validator and canonical writer join are currently a dependency,
not a supplied capability. The tests use an explicitly SYNTHETIC canonical
writer with real P1/SQLite; their records are component evidence, not native QA.

## Shared read-only capacity consumer

```js
const view = inspectLegacyMaintenanceWorkerCapacityFrom(ledger, owningTx);
// The existing authorized admission separately checks view.admission_available,
// remaining grants/budgets, currentness, native support and its physical fence.
```

The consumer requires the actual `PeerLedger` and its already owning P1
transaction before any planned or physical put. It accepts no caller capacity
or proof fields. It checks current paused origin/policy/record references,
canonical creation lineage, and exact legacy writer fences. It then recomputes
the entire original projection from the ledger's physically frozen legacy
tables; matching DATA alone cannot hide omitted jobs, history or unknown facts.
The layout5 read is limited to those exact fenced original tables, with their
original layout4 encoding; it does not migrate or use the retired Store writer.

Critical company/origin/record/version/event values are also matched to the
actual ledger connection's physical P1 metadata and bytes. A provider-shaped
view cannot supply a different policy or relabel another canonical writer.

The consumer reads every current slot and compares the complete inventory with
actual P1 slot metadata. It supports both normal P1 pages and the maintenance
planner's pages without `total`; neither can omit a physical slot. Every legacy
reservation must retain its UNKNOWN status and exact job/source identity.

The count is:

```text
all locally occupied or unproved ORIGINAL jobs
+ every active or UNKNOWN NEW execution slot
```

It uses the same existing `policy.worker_cap <= 3`, never a separate extra pool.
Legacy slots are retained as semantic reservations, not double-counted as a
second copy of the same original job. A local-closed failed job may count zero
while its UNKNOWN reservation and global applicability remain binding. Every
unconfirmed QA or other unproved job counts one. Malformed capacity holds.
New origin, frontier and other active/UNKNOWN execution slots all count; this
helper cannot release or refund them. A full cap returns no available admission.

Both approved integrations—origin maintenance and input-frontier maintenance—
must use this same view. They must keep their existing finite new invocation
units, model/review/frontier budgets, expiry, logical-target nonretry rules,
currentness checks and physical commit guards. No whole-domain qualification,
ordinary task/effect permission or old-to-new allowance conversion follows.
The integration must preserve the source's before-write historical verification
and get-only current-reference terminal checks; this reader is not for a
post-write historical read.

The owner-handover core's `reviewCapacity` also counts every active/UNKNOWN slot.
Future bounded owner-maintenance work may need the same separately qualified
local-capacity view after the owning CoS coordinates its source owner and actual
source/authority joins. That is a read-only dependency finding here. The
owner-handover core is unchanged, and this component grants no general capacity
waiver or additional approved consumer.

## Verification and remaining holds

The fictional tests exercise normalized immutable events and real P1 while
keeping all child births/closures and canonical mechanical records explicitly
SYNTHETIC. They cover failed/completed local equivalence, seven preserved UNKNOWN
failures, unconfirmed QA, combined origin/frontier capacity, missing or forged
proof, all-invocation history, raw/hash tampering, malformed capacity, full
inventory bounds, encoded identities, provider errors, stale source data and
missing/wrong producer joins. They assert no storage or usage changes.

No live inventory is qualified. A selected or partial job listing cannot establish
free capacity. The complete actual inventory, original
policy applicability, mechanical plan/review, current budgets, original native
support and actual context/wire fit can still hold. Source review and tests do
not perform company quarantine, native execution, adoption or production
activation.
