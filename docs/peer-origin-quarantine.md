# Checked origin quarantine backend

This is an internal source implementation, separate from the public read-only
`company_peer_adoption` preparation tool and the historical unpublished
`adoptPeers`. It registers no public apply, migration, grant, native launch or
resume action. Actual company operations require prospective founder authority,
the real caller producer, reviewed shared scheduler/native joins and independent
acceptance. Fictional source fixtures establish none of those facts.

## Frozen source and mechanical review

`origin-plan.mjs` exports `recordPeerOriginQuarantinePlan(root,actor,input)`.
The fixed host supplies `actor:{host,session_id,native_id}`; it is never a model
field. The owning Codex root has `session_id === native_id`. An existing layout4
database and its actual canonical owner are checked read-only before opening
the compatibility Store. Missing state is never initialized.

Input contains exact `source_instruction`, future `expires_at` within seven
days, a five-field peer `policy`, and a separately scoped finite `maintenance`
authority. Policy cannot exceed the existing three-worker/64KiB/context and
queue ceilings. Maintenance has `scope:'*'`, `source_instruction`,
`max_model_calls` and `max_review_calls`. These are NEW prospective maintenance
execution allowances, not legacy grants, provider billing units or a reset of
spent/expired permission. The original legacy counters remain byte-for-byte.
An optional reviewed `frontier:{protocol:'peer-origin-input-frontier-v1',
max_model_calls,max_review_calls}` selects explicit subcaps within those same
totals; its absence creates no frontier authority.

The source-generated plan freezes every current normalized row, position,
encoding and unknown extension, the complete original vault/event/schema and
company-sidecar inventories, exact old pins, validated legacy classification
frontier and canonical intake baseline. Boundaries are 10,000 entries,
64MiB source/archive admission, 16MiB per source value, and 1,000 company-sidecar
files/64MiB. Over-capacity fails without a complete-prefix claim. External paths
mentioned in text are retained references, not silently followed or qualified.

`validatePeerOriginMechanicalReview` requires one actual canonical legacy QA
review of this exact plan, its original native identity and original process
birth/closure journal, current context, independence, expiry and no negative
review. Its closed statement permits only `quarantine_peer_origin`. That old
native profile is historical mechanical evidence; it cannot qualify a new
protected maintenance participant.

There is no caller exclusion list. Canonical `readStorageIntake` proves every
post-baseline delta. Only the source-generated plan, exact producing QA job and
output/session records, and deterministic revision/time metadata may grow.
The QA job must be absent from the baseline. Its fresh queued/started/completed
lineage permits only the corresponding runtime fields to change; every final
invocation requires its own original requested/born/closed ordered proof, with
other job fields unchanged during process phases. Original event identity binds
sequence, timestamp, type and exact value bytes. The final expiry sample follows
the last fence/provider read immediately before the physical COMMIT.
Unrelated records, notices, controls, old jobs, archive history, schema or file
changes hold the plan. `originMechanicalReviewEligible` is the narrow pure
predicate for a coordinated paused legacy scheduler/worker join; it is not
automatically wired into those shared files by this cut. Standard legacy QA
context and original delivery must still fit their actual policy. A large
mechanical plan needs a separately checked complete streaming/frontier producer;
the backend does not accept a digest as semantic consumption.

## Atomic paused quarantine

`origin-quarantine.mjs` exports `quarantinePeerOrigin(root,actor,input)` with
exact `plan_id`, `review_ids:[one exact review ID]` and `source_instruction`.
It validates before creating a fresh fixed backup outside `.company`, copies
the canonical company backup, additionally preserves the historical
`storage-backup-*` files omitted by the general helper, verifies every file,
and reopens the backup to verify integrity and the complete original logical cut.
The separate complete manifest retains the general helper's original manifest.

Inside `BEGIN IMMEDIATE`, all review/current-source checks run again. Fixed SQL
fences retire writes to original company, event, normalized-entry and vault
tables before peer schema/layout work. The one layout transition cannot alter
the new pristine peer state through an old trigger; the layout table is then
fenced too. Any failure rolls back schema, fences and imported rows; the verified
backup remains evidence. No restoration operation is implemented or inferred.

The same company commits paused, with original owner/epoch, complete canonical
`control/pinned-team`, separately typed `control/origin`, complete lossless
archive manifests/ranges and legacy source homes. Every original unresolved
notice keeps exact source attribution and retrievable original summary/body;
a preview is explicitly incomplete. Uncertain old executions become occupied
`legacy_origin_reservation` slots with their original assignment unit and
unknown/global applicability. A release Boolean or plausible process journal
does not free capacity: honoring a completed old job's local release requires
its actual original requested/born/closed and completion/reconciliation event
and vault lineage. Failed/cancelled/unproven attempts stay UNKNOWN. Even a
verified local fact explicitly proves no whole-domain/remote closure.
Malformed capacity stays unknown. No old grants
become active peer grants; scheduler/publisher stay held. Retained aliases
exclude all old native contributors from the fresh maintenance lane.

Cold source readers are `readPeerOriginManifestFrom` and
`readPeerOriginSourceFrom`. Projection payloads use complete canonical JSON
chunks with exact offsets/body hash; no oversized projection is silently
clipped. Existing canonical pin readers resolve the same original immutable
values. No installed-team substitution occurs.

`observePeerOriginSidecars` checks the fixed company directory and records late
original files as required uncertain obligations. It invalidates the old seal
and retains both inventories without deleting files, releasing reservations or
changing the current pause decision. Unrecorded file changes block affected
currentness checks. This is a database-writer fence, not proof that every old
remote operation or credential is absent.

## Fresh original maintenance and conservative seal

`createPeerOriginMaintenance({ledger,actor})` returns an internal service.
`prepareOriginalPeerOriginMaintenance(service,{operation_id,kind,segments,
reconstruction_ref?})` supports `peer-origin-reconstruction` and
`peer-origin-review`. It requires the fixed source
`inspectOriginalOriginMaintenanceSupport` before any charge. The current source
without the distinct native join holds; caller flags cannot supply support.

The separate wire-preflight followup additionally requires the fixed
`preflightOriginalOriginMaintenanceContext(text)` and
`inspectOriginalOriginMaintenancePreflight(originalPlan)` producers. Before the
first P1 put or charge, the complete canonical context and fixed pure
`ORIGIN_MAINTENANCE_INSTRUCTION` must fit the actual whole first outgoing RPC,
including its escaped frame and envelope. The 64KiB context ceiling remains;
the whole outgoing RPC ceiling is 100000 bytes. The incoming 4000000-byte wire
budget is not an outgoing allowance. Missing exports or invalid source receipts
hold without admitting an attempt.

The immutable admission retains the exact closed twelve-field
`peer-origin-maintenance-first-rpc-v1` receipt: payload, instruction, frame and
recipe hashes; input, whole-RPC, frame, wire and context byte counts; the exact
policy context ceiling; and `native_identity: UNOBSERVED_GEOMETRY_ONLY`.
`frame_sha256` identifies the payload frame. Preflight uses the fixed 36-character
UUID geometry; it cannot claim an actual thread, native request hash, successful
execution or qualification. The original opaque plan remains private.
`originalPeerOriginMaintenancePreflight(cap)` rechecks the original current
capability and the same fixed source plan before returning that original plan
to the fixed host. Persisted DATA, copied objects and cold reads cannot recreate
it. The host must separately bind the actual fresh creation UUID, exact original
interpreter and actual request before its first model send. A bound capability
cannot pass the reserved-before-creation assertion again.

Each admission preserves an immutable original context/subject and charges one
new maintenance execution within unchanged global, worker and review limits.
It reserves an ordinary-authority-free logical participant and slot/effect.
Same-process replay returns the same private capability; cold replay cannot
recreate it or launch another execution. `inspectPeerOriginMaintenanceOperation`
returns persisted references/status instead. UNKNOWN executions retain their
charge and occupied reservation, including after expiry. An immutable logical
target index also prevents a new operation ID or reordered range vector from
retrying the same kind/source/reconstruction target. A separately reviewed
recovery/superseding target is required; changing the operation ID is insufficient.

The fixed fresh native creator must supply an original private creation token
to synchronous `bindOriginalPeerOriginNative`. The original assertion binds
actual thread birth, admission/context/kind, reviewed readonly profile and
source association before a model send. An old owner/membership/legacy token,
resumed legacy QA identity, selected native ID or JSON copy cannot substitute.
Reconstruction and review use separate fresh identities, independent of each
other, old contributors and current principals.

`peer-origin-maintenance-context-v1` includes the FULL exact pinned bundle,
canonical legacy current-meaning frontier, every remaining compulsory original,
current obligations/reservations, prior reviews and exact selected raw ranges.
`reviewedContext`/scoped/corpus canonical producer lineage is reused; unclassified
originals remain compulsory. The COMPLETE body must fit the existing policy and
64KiB maximum before any charge. A pin reference is not consumption. The real
company's near-64KiB pins therefore remain held until the separate qualified
input-frontier/stream/decomposition producer exists; this cut raises no cap.

The complete context also contains `response_contract`, derived from the same
closed keys, mapping coordinates, enums and text bounds as its kind's validator.
This is grammar DATA, never a verdict or authority. Reconstruction has no
verdict field and retains uncertain mappings globally with reasons. Review has
its exact reconstruction reference, Pass/Fail/Blocked vocabulary, blocker rules
and required original negative-review references. The fixed pure instruction
requires the entire canonical JSON response as the first submission and final
answer. Noncanonical whitespace or key order is a pure model-output rejection;
the full raw text remains evidence after genuine drain. Source grammar,
currentness, storage, provider and original-plan inspection errors still
propagate with their original identity and roll back all SQL. They cannot be
converted into rejected model output or a released reservation.

`prepareOriginalPeerOriginMaintenanceContext` supplies fixed framing only.
The original channel's complete exact range reads must independently establish
delivery before first immutable output. Completion consumes only the original
same-ledger/kind/admission/context owned-task drain token. It persists original
birth, charged admission/event chain, full context, exact output and scoped drain
facts. A genuine negative or rejected result is retained. It releases only the
new genuinely drained execution; group absence and remote closure remain
unproved. Expired/cancelled work and late diagnostics never backfill success.
Large diagnostics are losslessly chunked or explicitly marked retention-held,
always with a required uncertain notice and no reservation-release authority.

Completion distinguishes pure model-output validation from source/provider
failure by a private error identity. Invalid JSON and closed-schema violations
remain durable rejected outputs after a genuine drain. Current-state, pins,
archive/negative-proof and provider exceptions propagate unchanged and roll back
all SQL; they do not consume the original completion capability or drain token.
The same original completion can be retried after the read failure is corrected,
within its unchanged currentness/deadline and without a new model call.

`captureOriginSidecarContents` is the fixed internal inventory-and-bytes reader;
`originSidecars` strips its retained byte buffers. The fixed original POSIX helper
receives the original selected directory as inherited FD3. It uses `openat`,
`fstatat` and `fdopendir` on original descriptors, including nonblocking,
no-follow file opens; it never enumerates a pathname. It retains file/directory
descriptors and checks identity/mode/link count, size, nanosecond times and exact
directory entries before emitting a complete bounded binary frame. Ancestor
path substitutions cannot redirect that descriptor. Selected-directory changes,
omission or growth yield no accepted partial inventory. These bytes are DATA;
consuming them never grants company or native authority.
Only the exact root database snapshot files `company.sqlite`, `company.sqlite-wal`
and `company.sqlite-shm` are excluded. Other prefixed files and directory trees,
including `company.sqlite-journal`, remain complete ordinary sidecar inputs.
Missing verified helper deployment Holds before the mutable Store/database open,
any company writes or precharge. There is no pathname enumeration fallback. See
[the exact helper contract](peer-origin-sidecar-helper.md).

`sealPeerOrigin` requires complete exact original-source range coverage and
actual independent accepted review chains. Earlier overlapping negatives cannot
be omitted; a fresh qualified disposition must reference them explicitly after
delivery. Raw originals remain global. Narrow applicability can reuse only an
already canonical whole-source legacy scoped classification, retaining its
original proof plus the new exact qualification. The seal preserves original
slot refs/units/expiry/spent evidence and still commits paused.

`assertPeerOriginScopeFrom` cold-validates those actual original chains and
retained reservation refs. Unknown/global overlaps hold affected writes;
read-only preparation and actually proved disjoint applicability are separate
from NEW authority. `assertPeerOriginPhysicalFrom` additionally checks actual
original legacy fences, pin/current filesystem frontier in the caller's owning
snapshot; a coordinated consumer must repeat its terminal cutoff checks.
Neither function grants authority. The existing model `legacyOriginHold` and
public apply surface are unchanged. Explicit resume, ordinary membership/tasks,
environment qualification, scalable frontier and publication remain separately
reviewed joins.

The public legacy-plan producer must use
`recordPeerOriginQuarantinePlanAtEpoch(root, actor, epoch, input)`. Its explicit
positive epoch is checked against the current owner inside the original writer
transaction before capture or staging, then against the exact normalized owner
at the terminal commit fence. A same-session takeover invalidates the old epoch.
Missing exports or stale epochs Hold; public routing cannot fall back to the
legacy internal epochless helper. These checks do not grant mechanical QA or
maintenance execution.
