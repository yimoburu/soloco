Implementation began at `7b6d6d5` and incorporates upstream `b6ea56b`, preserving the concurrent backlog fixes.

This candidate connects outcome framing, prospective proposal handling and typed
recovery to existing runtime contracts. It preserves the separate development,
review, handover and execution permissions. It does not infer company adoption
or customer value from source tests.

Acceptance work:

- Explicit task outcomes retain objective, expected effect, observation,
  assessment period and exact supplied evidence through dependencies/checkpoints.
- Opt-in read-only operating proposals can feed subsequent work without changing
  accepted knowledge. Legacy outputs, notices, failures, unknown fields and
  changed obligations retain their conservative reconciliation path.
- Only typed capacity/resource holds can leave an unstarted task eligible for
  later scheduling. Unknown errors and uncertain attempts never auto-retry.
- A supplied-feedback workflow links proposed improvement, retained candidate,
  actual tests, independent review and observed feedback, preserving unmeasured
  business effects and founder time as unknown.
- Retained evaluations distinguish mechanical contracts, actual native behavior,
  human observation and adoption. Current capability reporting links exact proof.
