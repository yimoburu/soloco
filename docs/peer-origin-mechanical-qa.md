# Explicit pre-quarantine mechanical QA

This SOURCE component is a held interface. The current owner can record a
founder-attributed finite decision, prepare an immutable exact review packet,
and record a later grant for that exact packet. These records do not mechanically
authenticate the human producer. They never borrow post-quarantine maintenance,
bootstrap, owner-review, expired R6 or other historical allowances.

The original plan selects an exact decision reference with
`peer-origin-mechanical-qa-purpose-v1`, purpose
`quarantine-transition-review-only`. Preparation generates a fixed fresh QA job
template and the complete canonical assignment context after the plan commits.
The packet is DATA: no job, session or charge exists yet. Its exact normalized
pre-packet baseline and immutable originals authenticate the original context
through all later typed administrative changes. The fixed reader reconstructs
that original state and reruns the canonical context producer; it does not use a
caller exclusion or pretend changed current data is unchanged.

The later grant binds the exact immutable plan/cut/packet/context, requested
host/model/data scope, owner epoch/current policy generation and earliest
expiry. It permits at most one new original legacy QA assignment, at most17
original native invocations, at most200000 UTF8 context bytes and600000ms per
invocation. These are ceilings; real executor/catalog/profile/native fit remains
separately required. Requested scope is not an isolation proof. The exact primary
locator, quote and raw UTF8 hash are recorded as
`owning-cos-recorded-founder-instruction`, with human authenticity explicitly
`not mechanically established`.

Queue reservation requires the exact original grant reference, fixed approved
job/context and same actual writer transaction. It charges once, retaining every
failed/UNKNOWN attempt. Current normalized pointers, company/owner/epoch, physical
SQLite root, original source event chains, limits and complete typed intake are
checked. Worker currentness and next-invocation APIs use the original queued
receipt and original context, not ordinary changed-state context matching.
Bounded packet inspect/read returns exact4096-character Unicode-safe ranges;
historical reads do not assert current eligibility or execution authority.

The fixed E7 dependency is
`prospective-local-worker-inventory-producer.mjs` exporting
`inspectOriginalLocalExecutionInventoryFrom(actualDb)`. A complete retained row
census is insufficient: global execution cardinality and finite occupied and
remaining capacity must be known. Missing source or UNKNOWN cardinality Holds
production reservation/current invocation. There is no job-count permission
fallback. Positive bookkeeping fixtures use a clearly SYNTHETIC inventory
namespace and establish no genuine execution-capacity qualification. Actual
default-namespace tests retain zero charges/jobs when inventory is missing.

Supported public application must call the strict epoch-bound
`quarantinePeerOriginAtEpoch` and its selected validator. Old selectionless plans
Hold. The legacy internal compatibility function is not a public fallback. The
public origin route and generic dispatch for these review targets must enforce
the same actual original-grant/receipt guards; a paused eligibility predicate
alone authorizes nothing. Ed owns those queue/worker/public joins.

Source tests cover attributed metadata/once-only accounting, original context,
primary/op and epoch/policy changes, stale exact grants, UNKNOWN preservation,
call bounds, real local provider Error/TypeError/AggregateError identity/rollback,
complete large-packet Hold and actual missing/unknown execution-inventory Hold.
The tiny positive packet is54555 UTF8 bytes; a fictional500mandatory-input
complete baseline renders858099 characters and Holds before any packet/grant/job
or new spend. Neither measures the real company or native/model context fit.

Actual decisions, grants, company changes, dispatch, model/provider/native work,
migration and restoration remain unselected. Genuine E7 production/selection,
independent review, exact source/public/worker composition and future concrete
founder approval remain required.

The actual queue must call
`assertOriginalPeerOriginMechanicalQaReservationCommitFrom` with the SAME
original returned receipt as its LAST physical commit fence. A private WeakMap
binds that receipt to the original Store/owner/job/charge. JSON, inherited, cloned
or foreign-Store receipts do not qualify. The fence checks actual postimages and
original queue evidence, reads the final full state, then samples the deadline
after the last provider read. Late expiry rolls back every staged charge/job.

The strict public quarantine wrapper is epoch-bound and its selected validator
recognizes administrative rows only through the fixed private journal proof.
Existing internal compatibility helpers remain historical library paths, not a
supported public fallback. No full mechanical-QA/public/native qualification is
claimed by this held interface.

The current-source reader now replays every original queued job revision and
session change through the complete authenticated storage interval. Each
model-process request/birth/close must be an actual canonical job delta, obey
the original runtime transition grammar, preserve every other job field and
bind the original job, instance, worker and host. Other job phases preserve the
tracking journal exactly. Native-call spend derives from the original request
history; deleting or restoring current tracking cannot replenish it. A pending
original invocation blocks another request even while the numerical cap has
room. Request/child-close observations retain their narrow original scope;
they do not prove global or remote-domain closure or free capacity.

Transient task/lane changes remain disqualifying after current shape is
restored. Unsupported phase/session changes Hold rather than being treated as
administrative history. Genuine execution cardinality and source/native gates
still apply before any run; the fixture inventory is not their qualification.
