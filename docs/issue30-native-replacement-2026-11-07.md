# Native session replacement qualification

Issue [#30](https://github.com/yimoburu/soloco/issues/30) has a new bounded native
replacement result. It remains open for its complete responsive/outcome and
supported-host acceptance requirements.

The [allowlisted receipt](../evals/native-session-replacement-20261107/summary.json)
records eight real model calls with five distinct native histories: outgoing
CoS, incoming CoS, outgoing worker, incoming worker and independent QA. The
incoming CoS resumed its own new native session to reconstruct the complete
exact frozen semantics. Its reconstruction preserved the current objective,
both item IDs, commitment, unresolved supplier blocker, preparation-only
authority and next permitted action, while rejecting the obsolete amber value
in favor of violet. The old native chat transcript was not supplied.

Independent native QA read all compulsory semantic ranges on its own session.
The runtime accepted that exact review and reconstruction before preparation
resumed. The fresh worker preserved the same obligations; the old owner could
not mutate state, the old worker job stayed unchanged and the unresolved notice
remained unresolved. All worker process closures were confirmed. No shipping
packet or business action was accepted by this fixture.

The run took 183.31 seconds, including native cold starts, reconstruction,
streaming QA, control operations and both worker calls. Four direct control
calls had a 21.12 ms median and 65.20 ms observed maximum. These are descriptive
measurements of one fictional run, not a matched latency improvement or
population-tail estimate. The serial/concurrent comparisons in
[issue #16's evaluation](issue16-repeated-evaluation-2026-11-07.md) concern a different
bounded workload and cannot become a before/after benchmark of this runtime.

The initial harness stopped after one CoS call because its public control
arguments were invalid. That held attempt remains retained. The second run used
the repaired clean source commit `eb329e3`; HEAD, tree and harness hash were
verified unchanged immediately after execution. The exact executed harness
and test are frozen beside the receipt. Later harness hardening rejects
non-object JSON, performs its own final source check and labels its diagnostic
copy local-only. It does not regrade the first attempt or represent another
native run.

The fixture uses synthetic lifecycle bindings for its fictional project. It
does not qualify real host Hooks invocation, desktop lifecycle, a killed live
model process, cross-host recovery or accumulated private-company continuity.
Current records are a small deliberately supplied corpus; no actual company
ownership, pins, installation or adoption changed. Real founder time and
interruptions remain unmeasured, as confirmed by the founder. Raw model outputs
and native host diagnostics remain local; published evidence uses a strict
allowlist of hashes, counts, controls, checks and timings.
