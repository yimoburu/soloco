# Local test preflight recovery

This source maintenance component removes the one-second `sw_vers` fork from validation fingerprinting, retains structured failure metadata, and adds an explicit, single-use recovery operation for a test worker that provably did not enter its runner. It does not retry automatically, create another Engineering generation, refund an attempt, revive a grant, extend expiry, waive QA, install a runtime or change a retained candidate.

`tests_executed:false` means that harness evidence was absent. It is never sufficient recovery proof. Started, unknown, cancelled, interrupted, quarantined, reused, postflight and no-TAP attempts remain held. A candidate with acceptance or submitted negative candidate/test QA remains held. Active or unclosed resource claims remain held. Inspection preserves the original records and uncertainty.

## Fixed system descriptor

`system-build.mjs` reads only `/System/Library/CoreServices/SystemVersion.plist` and extracts `ProductBuildVersion`. Apple's Installer `system.version` documentation identifies this file as the current system version; Apple's published CoreFoundation `CFUtilities.c` reads the same fixed path and maps `ProductBuildVersion`. The source explicitly avoids caching because the descriptor can change while applications remain running.

The implementation reads afresh at each existing preflight/postflight fingerprint boundary. It requires a root-owned regular nonlink file, one link, no group/world write, at most 16 KiB, `O_NOFOLLOW|O_NONBLOCK`, stable descriptor/path metadata across the read and strict supported UTF-8 XML plist syntax. Unsupported/binary plists, duplicate keys, custom entities, bad build strings, errors and races hold closed. There is no subprocess, cached build, environment/caller-selected path or fallback. The fingerprint binds the extracted build, descriptor protocol and exact descriptor SHA256, and includes the reader module among dependency bytes. Existing fingerprint inputs and legacy manifest validation remain supported. A descriptor read bound is not a promise that a pathological local filesystem syscall cannot stall.

Primary references:

- https://developer.apple.com/documentation/installer_js/system/1812284-version
- https://github.com/apple-oss-distributions/CF/blob/main/CFUtilities.c

The historical failure discarded its subprocess status, signal, stderr and underlying error. Its original system subcause remains unknown. A later foreground shell success does not establish worker success or explain that old failure.

## Candidate-free worker diagnostic

Use `company_develop` with `action:"diagnose_preflight"`, current root/session/epoch and a nonempty `source_instruction`. This reserves a real `development_preflight` job and starts the ordinary finite runtime worker entry point. It takes no plan, candidate, receipt, test path, command, executable, environment or proof selector. It runs the actual fingerprint environment provider over a newly owned empty diagnostic directory with no candidate and no test runner/watchdog invocation. Existing trusted runtime/library and Node-flag discovery probes may run fixed trusted probe code; no candidate code is loaded.

The detached diagnostic child has a 45-second timeout while its launcher remains alive. A killed, unfinished, stale, cancelled or unknown diagnostic is not recovery evidence. The worker checks its own implementation identity, owner, epoch, authority and 45-second completion interval. The runtime artifact contains safe runtime identifiers, descriptor commitments and a hash of the complete private environment; raw environment values and dependency paths are not copied into it. Temporary empty diagnostic directories are removed when possible. Diagnostic fingerprint, spawn and early worker-start failures retain bounded typed metadata and a SHA256 commitment to the error message; raw provider paths and messages are omitted from diagnostic jobs, receipts, notices and synchronous start-error responses. Ordinary local test receipts retain their existing directory, error, stdout and stderr contract. Their validation manifest keeps host dependency paths and environment values as hashed commitments. A diagnostic is not a successful test receipt or a reusable validation result. An owner must inspect a canonical successful Submitted diagnostic before requesting recovery; it must be at most five minutes old and current at recovery admission. Recovery still fingerprints its actual candidate afresh and never substitutes a diagnostic's fingerprint.

## Future worker launch facts

The test worker writes `execution_provenance` on its canonical job with a runtime nonce, PID, implementation identity, phase and monotonic `launch_intent`/`runner_entered` flags. After candidate preparation it durably records `phase:"preflight"`. Immediately before entering `runLocalTests` it rechecks current owner/grant/source/candidate/evidence/runtime identity and original expiry, then commits launch intent **before** any watchdog or test-runner call. Once intent is set, no error or missing TAP can turn it back into zero execution. Final receipts bind the exact same protected facts and preserve actual runner output when a later fingerprint fails. Publication rechecks currentness; stale results are quarantined.

A future canonical failed attempt is eligible only when both runtime job and receipt agree on the protected current-implementation preflight facts with launch intent false and runner entry false. Preparation/materialization failures outside that phase remain held. JSON API callers and model outputs have no fields for choosing these facts or dependency functions. In-process provider/launcher seams exist only for controlled source regression tests.

## Exact legacy qualification

Legacy receipts have no durable launch phase. Generic legacy retry is unsupported. The only supported source profile is the exact M98 `develop.mjs` SHA256 `4e6bbae8350be76e509dea229dcb548624094fc11190dd7b732491cd6310a2f8` and `local-sandbox.mjs` SHA256 `1fe6bc9e3464dfb27169cb3446f94654ac4499c49afd99e44882a9d0cce47e3f`.

For that profile, the canonical no-reuse failure must have exactly the old minimal result shape: null exit, false harness flag, failed status, the unique `Cannot fingerprint system build for validation reuse` error, candidate SHA, exact scope test paths/limits, retained directory and finish time. Runner output/phase/manifest/reuse fields disqualify it. The exact old first-fingerprint branch precedes runner entry; the old postflight catch normally preserves an already-returned result. The old internal IPC accepted `message.result` without a schema check. Consequently the minimal shape alone cannot exclude an unknown or malformed historical helper. This route requires an independent qualification of the complete historical runtime and installation evidence and remains explicitly **source-bound inference**, not a fabricated past phase, PID, termination or timeout attestation.

The supported preparation sequence is:

1. Save a normal Draft artifact containing JSON `{protocol:"legacy-M98-preflight-runtime-sources-v1",files:{"develop.mjs":"<whole exact text>","local-sandbox.mjs":"<whole exact text>"}}`. Save the complete relevant installation/provenance evidence as normal artifacts. These are data, not grants or proofs.
2. Call `company_develop` with `action:"prepare_preflight_qualification"`, current root/session/epoch, original `plan_id`, `candidate_id`, exact old `receipt_id`/`receipt_sha256`, `legacy_source_id`, one to eight `installation_ids`, and explicit `source_instruction`. The runtime verifies the original current grant, fresh candidate context, original sources, retained exact directory, canonical old job/receipt and closed attributable producer. It creates a Submitted runtime target containing a recomputed **compact canonical binding view**, both full M98 modules and the full selected installation records.
3. Use the existing independent QA assignment flow with `review_of` that target. The target is mandatory whole inline; no supplemental read marker or one-character range substitutes for it. The normal context builder measures the actual current governing frame before dispatch. The narrow phase claim does not require copying the full P4 source/candidate/semantic assessment corpora; the runtime independently binds those exact originals. The full original and candidate code and required semantic inputs remain mandatory for later full code QA.
4. QA must assess historical installation, complete own-watchdog behavior, exact source branch and unresolved uncertainty. The prompt requests `permitted_action:"qualify_preflight_recovery"`, a bound `preflight_recovery` object, no blockers and an honest verdict. This Pass qualifies only the narrowly stated historical source inference. It is not `accept_local_development`, a passed test, authority to run, or extra generation capacity. Missing evidence requires Fail/Blocked.
5. Recovery requires a canonically completed, physically closed, current QA job with native and instance identities independent of the producer and owner. It checks exact target/review/job hashes, full inline context and all source/installation record hashes. It seals those facts and revalidates them at worker start, launch, polling, publication and acceptance. To keep a reviewed source binding current through the operation's own bookkeeping, it reconstructs exactly the old candidate run pointer while excluding only the protected new recovery/history fields; every other candidate field, record, obligation, notice and context fact must still match.

The controlled source tests use real SQLite storage, normal `company_save`, `dispatch` and `work` validators with a synthetic adapter and explicit timing. They do not establish an actual native QA qualification for any live legacy receipt.

## Explicit single-use recovery

Call `company_develop` with `action:"recover_preflight"`, current root/session/epoch, original `plan_id`/`scope_sha256`, exact `candidate_id`/`candidate_sha256`, exact old `receipt_id`/`receipt_sha256`, successful current `diagnostic_id`/`diagnostic_sha256`, and nonempty `source_instruction`. Supply `legacy_qualification_id` only for the closed qualified legacy route. No reuse flag is permitted.

The request atomically checks the still-current **original** authorization and fresh original candidate context. A changed authority, ownership epoch, source, configured ceiling, pause/revoke, original expiry, active/unknown work, scratch directory, unexpected file, source link, negative QA or acceptance holds recovery. There is no alternate current-authority grant or historical-context bypass in this component. A governing maintenance decision that actually stales the original grant therefore requires a separately designed prospective path; this API does not revive it.

The retained source directory is verified in place and must have no `.scratch`; it is never deleted, rematerialized, aliased to a different candidate or presented as validation reuse. The transaction appends the original `development.run` to `run_history`, records the explicit owner request and exact subject/proof/diagnostic bindings, consumes the candidate's one recovery and reserves one new physical test-worker job. The old scope, authorization, generation attempts, expiry, jobs and receipts remain unchanged. Read-only scoped context can retain the original completed software run through its exact archived tuple, consumed recovery request, original receipt/job hashes and replacement-job binding. The failed test result remains failed. Duplicate or conflicting history, changed provenance and missing canonical records hold; this historical closure grants no test, retry, validation reuse or review acceptance. The existing generation attempt limit stays exhausted. A failed worker spawn consumes the recovery too; it is not a reason to reset state.

Historical source closure validates the software writer's six candidate-pointer/job states: `queued/queued`, `queued/running`, `queued/cancelled`, `failed/failed`, `completed/completed` and `quarantined/quarantined`. The first four have no replacement receipt; the terminal states bind the exact replacement receipt and its canonical producer closure. A failed or quarantined terminal payload remains evidence. These checks permit historical retrieval after a pause and grant no new execution authority.

The candidate pointer plus exact prior receipt/candidate/scope hashes form the admission CAS. Repeating a recovery request rejects without launching a second worker. If a response is lost, inspect/read the candidate's `preflight_recovery`, `run`, request artifact and job; recover the persisted outcome through readback. Do not repeat mutations, clear records or use a different executor.

A new passing test receipt receives ordinary independent **full code QA** and the existing exact candidate/receipt acceptance checks. Its review context automatically includes the preserved old failure, owner recovery request, actual diagnostic and any legacy qualification. No failed receipt is relabeled Pass, no old negative is erased, and no source integration occurs.

## Qualification boundary

This is ordinary source preparation and controlled regression evidence. It does not install or trust a runtime, execute the live P4 candidate, create a real native specialist/QA session, qualify a live legacy receipt, adopt protected peer capabilities or change company grants/allowances. Compatible release/review and any later explicitly authorized live operation remain separate. Original failures and unknowns are retained.

Diagnostic jobs are software activity with no requested or observed model and contribute zero specialist assignments in both full and normalized public usage views. Progress separately attributes diagnostic receipts to diagnostic workers and recognizes only the exact typed qualification/recovery context forms. Retained prior test runs are displayed through their exact recovery request/history binding; test acceptance and prerequisite rules remain unchanged. Generic specialist timeout reconciliation remains unchanged and retains uncertainty.
