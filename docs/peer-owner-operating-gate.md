# Ordinary work during owner handover

The shared model reads the canonical owner operating state before a business
command or its cached receipt. A pending or reconstructed replacement cannot
act as an active owner. Independent acceptance activates the owner while the
company remains paused; ordinary work stays held until the dedicated owner
lifecycle records its explicit resume. Generic `company/resume` cannot replace
that transition, even after a dedicated resume has occurred.

The proof uses immutable begin, acceptance, activation and resume receipts plus
their exact supporting versions. Mutable readiness flags and caller claims do
not qualify it. The reader imports only the ledger; it creates no transactions,
model calls, native capabilities or grants. Existing legacy-origin denials remain.

After dedicated resume, verified source diagnostics can append an old phase and
require a notice without silently blocking ordinary work. The reader verifies
that exact append lineage and retains the original UNKNOWN slot/effect checks.
A supported notice disposition preserves its immutable first version; it does
not release uncertainty. Pending or activated handovers retain stricter checks.

An ordinary command under a controlled handover uses the guarded planning path.
When an existing unguarded path first discovers that state, a source-private
identity signal aborts the read-only transaction before command lookup or any
mutation. One fresh guarded transaction reselects and validates the actual state.
This repeats no host/native attempt or model call and renews no allowance.

Checked current heads and actual authorizing grants are captured before flush.
The terminal guard checks those heads through its get-only provider; it does
not query immutable history after writes. Public writes are sealed after the
plan. Task-bound clients and the production membership writer apply the same
owner proof before their command or write callback.

Two existing evidence lanes retain their original checks: protected runtime
`task/process`, `task/finish` and `task/closure` observations, and required
`notice/create` intake. The observation exception requires the original protected
host interface. It supplies no business authority, sender impersonation, new
attempt, owner qualification or automatic release of UNKNOWN reservations.
An old result remains immutable; additional output after a retained UNKNOWN
result requires a separate evidence producer. A later closure is separate from
the result and still requires its original physical proof.

Same-owner pause/resume retains its existing behavior. Owner-control source
fixtures with explicitly synthetic native seams establish source mechanics
only. They do not establish deployed native qualification, adoption or operating
readiness for an existing company.
