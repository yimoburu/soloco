# Physical fence for normalized legacy writers

This unpublished component addresses one mechanical boundary: after the draft peer-adoption transaction commits layout 5, legacy normalized archive rows and the layout marker must remain unchanged. It is not production adoption, protected host or membership qualification. Do not route, expose or install this migration draft as an adopted company operation.

The migration imports the actual canonical `resourceClaims` producer from `state-projections.mjs`. It retains the existing pause, uncertain-execution, owner, pinned-team, complete source-cut, review and backup checks. A redundant inner `plan` binding that prevented the draft transaction from running was removed. No Boolean permission override was added.

Inside the actual `BEGIN IMMEDIATE` adoption transaction, six persistent archive guards deny `INSERT`, `UPDATE` and `DELETE` on `state_entries` and `immutable_values` BEFORE any peer-schema creation or layout transition. The layout update must then change exactly one row from 4 to 5; only afterward are the three layout-marker guards installed. All nine guards are created before imports and commit. Trigger names cannot be preinstalled as permissive substitutes: creation fails on a name collision, and stored definitions are checked. Existing company sentinel guards remain unchanged. `BEFORE INSERT` also prevents `REPLACE` from silently deleting/replacing a protected row, independently of SQLite's recursive-delete-trigger setting.

The guards are installed before legacy-reference imports and before commit. A failure rolls back peer schema, imports, guards and layout together; the real pre-adoption backup remains retained. `legacy_writers_fenced` becomes true only after those guards and the transaction commit succeed. Adoption authority and expiry are checked again in the fresh transaction and at the final pure commit cutoff. An expired backup interval or late expiry after imports cannot commit the change.

The exact historical v0.6.10/v0.6.13 writer is retained byte-for-byte as a test fixture. Its unchecked whole/selected deletion and early immutable insertion can modify normalized-v4 rows before a later modern-shape error. Tests first exercise these operations in rollback-only controls. They then use the actual checked draft path in temporary normalized-v4 SQLite, with explicitly synthetic old native/review/environment labels, and verify old APIs, already-open connections and already-prepared SQL all fail without archive changes after adoption. Legitimate peer-family writes/events and exact `resolveLegacy` reads remain usable. Unknown originals, failures, exhausted attempts, ordering and encoded identities stay preserved.

These are SQL row-mutation guards, not protection against a privileged actor that can drop tables/triggers, replace the database file or change host credentials. No qualified broker/OS boundary, P8 authentication, principal incarnation policy, trusted native review or full meaning-preserving production adoption is established. The draft's environment labels and immediate-active `registerPrincipal` remain known unqualified semantics. Actual production adoption stays held for separately qualified P8/broker/meaning review, native Engineer adoption and independent QA. This component grants no execution, resume, claim release or publication authority.

The public legacy `selection_usage` is derived assignment telemetry, not a spent-allowance ledger: it counts non-development-test jobs, including queued and failed jobs, and excludes CoS conversation and upgrade calls. It does not measure successful model calls, tokens, cost or quotas. The root `selection_usage` object in this mechanical fixture is a synthetic unknown extension whose exact bytes are preserved; its `model_calls` spelling does not establish a real legacy counter shape. Excluding this telemetry from the source cut therefore does not, by itself, prove that an allowance was reset.

The peer model's `model_calls` counter instead records admission reservations, charged before launch and retained for failed or uncertain attempts. Neither assignment counts nor upgrade prompt-character totals can be converted into that unit without an explicit, source-grounded contract. This mechanical component implements no such conversion. Original grants, attempt identities, spent or uncertain reservations, expiry and restrictions remain binding in their own scopes. Production adoption and resume still require qualification of their preservation or explicitly authorized translation, protected pending-membership/P8 treatment, broker and host boundaries, and complete current meaning. Preserving an archive does not grant fresh spending or prove that the draft's new peer control accounts for every original obligation.

Preexisting input-schema triggers are also within this mechanical boundary. A layout trigger that already exists before planning cannot delete an original entry, reorder it, insert data or change immutable bytes during the intended transition. Archive guards run before that transition; refs-only source-cut rechecks are not a substitute because a blob can change without its stored SHA reference changing. Paired harmless input triggers remain valid. Failure rolls back the transition and newly created guards/schema while retaining the real backup and original input schema. No public bypass flag or callback is added.
