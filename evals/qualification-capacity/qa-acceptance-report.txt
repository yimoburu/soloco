**Concrete minimum-scope risks**

1. `projected()` caches already-partitioned historical `parts` by source identity. A new profile must distinguish partition derivations or repartition the cached semantic tree; otherwise cache order can select the wrong units.
2. Binary topology and two-child reconciliation are hardcoded. If “fanout” means changing tree arity, topology, target validation, ordered supports and canonical child validation must agree. If it means execution concurrency, leave arity unchanged.
3. Output instructions and validators use global constants; the worker separately uses a 100,000-character adapter ceiling and rejected-output retention limit. Raising one constant is insufficient, and larger valid limits must not cause silent receipt truncation.
4. Failure notices enter the current semantic subject. Improved attribution must distinguish the initiating overflow from downstream cancellation without suppressing consequential notices or weakening freshness.
5. `jobReviewWindow()` does not itself verify that the target is an ordinary handover. Explicitly prevent qualification jobs from acquiring that separate timing capability; a late canonical rejection would waste execution.
